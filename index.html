    llm-balancer

    One call, many models. Group LLM models into pools; when one fails, the next one answers, and the failing one sits out a cooldown.

    🔁 Fallback

    Models of a pool are tried in order until one answers.

    🩺 Model health

    A failing model is skipped for a cooldown chosen by the kind of failure.

    ⏱️ Time budgets

    A timeout per attempt and a time limit for the whole request.

    🔌 Any vendor

    Gemini and Ollama built in; any other through one small interface.

    🧷 Type-safe

    Pool names and model ids are typed from your configuration.

    📡 Observable

    One event hook for logging. Events never carry prompts or answers.

    How a request is handled

    balancer.model(pool).converse(request):

    1. Orders the pool's models: healthy ones first, in pool order, then unhealthy ones whose policy allows a last resort. Unhealthy models without it are skipped until their cooldown ends.
    2. Calls each model with an AbortSignal that fires after attemptTimeoutMs, capped by what is left of requestBudgetMs. Models left when the budget is used up are skipped.
    3. Returns the first answer and marks that model healthy.
    4. A failed attempt puts the model on a cooldown chosen by its failure kind and moves on to the next model.
    5. Content blocked by a vendor's safety filter stops the chain at once with LlmContentBlockedError: the next model would most likely block it too, and the model is not at fault, so it gets no cooldown.
    6. When nothing answered, throws AllModelsFailedError with the reason for every model.

    Each model is called at most once per request. The same model may appear in several pools; its health is shared between them.

    Runtimes

    The core uses web-standard APIs only (fetch, AbortController, timers), so it runs on Deno, Node.js 20+, Bun, Supabase Edge Functions and Cloudflare Workers. Keep API keys on the server: a balancer in the browser would expose them.

    Create the balancer

    import { LoadBalancer } from '@vetrox/llm-balancer';
import { gemini } from '@vetrox/llm-balancer/gemini';
import { ollama } from '@vetrox/llm-balancer/ollama';

export const balancer = new LoadBalancer({
  providers: [
    gemini({ apiKey: GEMINI_API_KEY }),
    ollama({ baseUrl: 'http://localhost:11434' }),
  ],
  pools: {
    default: [
      { provider: 'gemini', model: 'gemini-2.5-flash' },
      { provider: 'gemini', model: 'gemini-2.5-flash-lite' },
      { provider: 'ollama', model: 'qwen3' },
    ],
    cheap: [{ provider: 'gemini', model: 'gemini-2.5-flash-lite' }],
  },
});

    Create the balancer once (at startup, or as a singleton in your DI container) and reuse it. Model health lives inside it; a new balancer per request would forget every cooldown.

    Send a request

    const answer = await balancer.model('default').converse({
  system: 'You are a concise assistant.',
  messages: [{ role: 'user', content: 'Name three prime numbers.' }],
  maxOutputTokens: 200,
});

    Request shape

    interface ConverseRequest {
  system?: string;          // trusted instructions, sent through the vendor's system channel
  messages: Message[];
  maxOutputTokens?: number; // thinking models count reasoning tokens towards it too
}

interface Message {
  role: 'user' | 'assistant';
  content: string | Part[];
}

type Part =
  | { type: 'text'; text: string }
  | { type: 'image'; data: Uint8Array; mimeType?: string }; // detected when omitted

    The same request object is replayed on every model of the chain. Images are base64-encoded once per request, however many models are tried. When mimeType is omitted it is detected from the bytes (PNG, JPEG, WebP, GIF).

    Configuration

    Every option of new LoadBalancer(config).

    new LoadBalancer({
  providers: [gemini({ apiKey }), ollama({ baseUrl })],
  pools: { default: [/* models in fallback order */] },
  health: {
    defaultCooldownSeconds: 90,
    byKind: {
      rate_limited: { cooldownSeconds: 60 },
      auth: { cooldownSeconds: Infinity },
      invalid_response: { cooldownSeconds: 20 },
      overloaded: { cooldownSeconds: 15, lastResort: true },
    },
  },
  timeouts: { requestBudgetMs: 60_000, attemptTimeoutMs: 25_000 },
  onEvent: (event) => console[event.level](event.type, event.data),
  healthStore: new MemoryHealthStore(),
});
    Option Default Meaning
    providers required Every provider the pools use; names must be unique
    pools required Pool name → models in fallback order
    health.defaultCooldownSeconds 60 Cooldown for every kind without its own
    health.byKind see below Per-kind cooldownSeconds and lastResort
    timeouts.requestBudgetMs 60000 Time for the whole fallback chain of one request
    timeouts.attemptTimeoutMs 25000 Time for one model, capped by what is left of the budget
    onEvent none Logging hook; exceptions thrown by it are ignored
    healthStore new MemoryHealthStore() Where model health is kept (Health store)

    Pools

    A pool is a list of { provider, model } in fallback order. Pool names become a type: balancer.model('typo') does not compile. The model field is typed by its provider, so built-in providers autocomplete known model ids and still accept any other string.

    Failure kinds

    Providers classify every failure. The kind decides how long the model is out and whether it may still be tried as a last resort, after every healthy model of the pool has failed.

    Kind Typical cause Last resort by default
    rate_limited HTTP 429, quota used up no
    auth HTTP 401 / 403, bad key no
    not_found HTTP 404, unknown or unpulled model no
    overloaded HTTP 503 yes
    timeout attempt timeout, HTTP 408 yes
    server_error other HTTP 5xx yes
    invalid_response empty or unreadable answer yes
    unknown anything else, including network errors yes

    Health policy

    interface HealthPolicyConfig {
  defaultCooldownSeconds?: number;                          // default 60
  byKind?: Partial<Record<FailureKind, FailurePolicy>>;
}

interface FailurePolicy {
  cooldownSeconds?: number; // Infinity = out until the process restarts
  lastResort?: boolean;     // may it be tried when every healthy model failed?
}
    • Every kind uses defaultCooldownSeconds unless byKind overrides it.
    • Fields left out of an override keep their defaults.
    • When the vendor says how long to wait (retryAfterSeconds, for example Gemini's RetryInfo on a used-up daily quota), the cooldown is never shorter than that.
    • Use lastResort: false when retrying cannot help before the cooldown ends (a used-up quota, bad keys).

    Timeouts

    Every attempt gets attemptTimeoutMs, capped by what is left of requestBudgetMs. When the time runs out the provider's AbortSignal fires and the balancer stops waiting even if the provider ignores the signal. A timed-out attempt is a timeout failure; models left after the budget is spent are reported as skipped.

    Validation

    The configuration is validated in the constructor. No pools, an empty pool, a pool that lists a model twice, a model of an unknown provider, two providers with the same name, or a negative or non-numeric timeout or cooldown throw BalancerConfigError at startup instead of failing on the first request.

    Errors

    What can be thrown, by whom, and when.

    Thrown by Error When
    new LoadBalancer() BalancerConfigError invalid configuration
    balancer.model(pool) BalancerConfigError pool not configured (only reachable without type checking)
    handle.converse() AllModelsFailedError no model answered
    handle.converse() LlmContentBlockedError a vendor's safety filter blocked the content
    gemini(), ollama(), openAiCompatible(), openRouter(), providersFromEnv() BalancerConfigError missing API key, invalid base URL

    AllModelsFailedError

    class AllModelsFailedError extends Error {
  readonly pool: string;
  readonly failures: readonly AttemptFailure[]; // every model, in the order handled
}

interface AttemptFailure {
  provider: string;
  model: string;
  kind: FailureKind;
  message: string;
  skipped: boolean; // true: not called at all (cooling down, or out of time budget)
}

    LlmContentBlockedError

    Carries reason (for example prompt: SAFETY). It ends the chain and does not put the model on a cooldown.

    LlmProviderError

    What providers throw for a classified failure. The balancer catches it and reports it inside AllModelsFailedError.failures; your code normally never sees it. 

    new LlmProviderError({
  kind: 'rate_limited',     // FailureKind
  message: 'Quota exceeded',
  status: 429,              // optional HTTP status
  retryAfterSeconds: 30,    // optional; the cooldown is never shorter
  cause: originalError,     // optional
});

    Handling errors

    import { AllModelsFailedError, LlmContentBlockedError } from '@vetrox/llm-balancer';

try {
  return await balancer.model('default').converse(request);
} catch (err) {
  if (err instanceof LlmContentBlockedError) return refuse(err.reason);
  if (err instanceof AllModelsFailedError) return serviceUnavailable(err.failures);
  throw err;
}

    Events

    One hook for logs and metrics, with a suggested log level.

    new LoadBalancer({
  // ...
  onEvent: (e) => logger[e.level](`llm_${e.type}`, e.data),
});
    type level data
    attempt info pool, provider, model
    attempt_failed warn pool, provider, model, kind, cooldownSeconds, lastResort, error
    content_blocked warn pool, provider, model, reason
    all_models_failed error pool, failures
    • Events never contain prompts, images or answers.
    • An exception thrown by onEvent is ignored and never breaks a request.
    • BalancerEvent is a discriminated union: switch on type for typed data.

    Health status

    Inspect every model at any time, for example in a health-check endpoint:

    for (const m of await balancer.status()) {
  console.log(m.provider, m.model, m.pools, m.healthy, m.cooldown);
}
// gemini gemini-2.5-flash ['default'] false
//   { kind: 'rate_limited', reason: '...', until: 1760961234000, lastResort: false }

    One entry per distinct model, in the order they first appear in the pools. cooldown.until is epoch milliseconds (Infinity for a cooldown that lasts until the process restarts).

    Providers

    Built-in Gemini, Ollama and OpenAI-compatible APIs, env helpers, and your own.

    Gemini

    import { gemini } from '@vetrox/llm-balancer/gemini';

const provider = gemini({
  apiKey, // name: 'gemini'
  thinkingLevels: { 'gemma-4-31b-it': 'MINIMAL' }, // optional, per model
});
    • model autocompletes known Gemini ids and accepts any other string.
    • HTTP statuses map to failure kinds as in Configuration.
    • HTTP 429 carries the retry delay from Gemini's RetryInfo.
    • Safety blocks of the prompt or the answer become LlmContentBlockedError.
    • An empty answer becomes invalid_response.
    • thinkingLevels sets MINIMAL, LOW, MEDIUM or HIGH per model. Less thinking answers faster (Gemma 4 with its default thinking can take minutes on a long prompt). A level the model does not accept is rejected by the API with HTTP 400.
    • Throws BalancerConfigError for an empty apiKey.
    • For tests: new GeminiProvider(models) with your own IGeminiModels (generateContent).

    Ollama

    import { ollama } from '@vetrox/llm-balancer/ollama';

const provider = ollama({
  baseUrl: 'http://localhost:11434', // name: 'ollama'
  fetch: myFetch,                     // optional: proxies, tests
});
    • Uses /api/chat; maxOutputTokens becomes num_predict.
    • A model that is not pulled answers 404 and becomes not_found.
    • Throws BalancerConfigError when baseUrl is not an http(s) URL.

    OpenAI-compatible APIs

    import { openAiCompatible } from '@vetrox/llm-balancer/openai-compatible';

const provider = openAiCompatible({
  name: 'mistral',                    // the name used in pools
  baseUrl: 'https://api.mistral.ai/v1',
  apiKey,                             // optional: Authorization: Bearer
  headers: { 'X-Custom': 'value' },   // optional
  modelOptions: { 'mistral-small-latest': { temperature: 0.7 } }, // optional, per model
  fetch: myFetch,                     // optional: proxies, tests
});
    • Any server with /chat/completions: Mistral, Groq, OpenRouter, vLLM, LM Studio, ...
    • Images go as image_url parts with a base64 data URL.
    • HTTP statuses map to failure kinds, also when the server puts an error with a status into a 200 answer.
    • HTTP 429 carries the delay from Retry-After or X-RateLimit-Reset.
    • finish_reason: "content_filter", a refusal or a moderation rejection becomes LlmContentBlockedError.
    • An empty answer, or one cut off by the token limit before any text, becomes invalid_response.
    • modelOptions cannot replace model, messages, stream or max_tokens.
    • Throws BalancerConfigError for an empty name or a baseUrl that is not an http(s) URL.

    OpenRouter

    import { openRouter } from '@vetrox/llm-balancer/openrouter';

const provider = openRouter({
  apiKey,                                // name: 'openrouter'
  appTitle: 'My app',                    // optional: X-Title
  appUrl: 'https://example.com',         // optional: HTTP-Referer
  reasoning: { 'openrouter/free': { effort: 'low' } }, // optional, per model
});
    • An OpenAI-compatible provider preset for https://openrouter.ai/api/v1.
    • reasoning limits how long a reasoning model thinks (effort, max_tokens or enabled: false). Free reasoning models can think for minutes on a long prompt.
    • A used-up daily limit of free models (HTTP 429) is rate_limited with retryAfterSeconds until the reset.
    • Throws BalancerConfigError for an empty apiKey.

    From environment variables

    import { providersFromEnv } from '@vetrox/llm-balancer/env';

const providers = providersFromEnv();
// GEMINI_API_KEY  -> gemini()

    Your own provider

    interface ILlmProvider<Name extends string = string, Model extends string = string> {
  readonly name: Name;
  converse(request: ConverseRequest, model: Model, signal: AbortSignal): Promise<string>;
}

    Rules for implementations:

    • Pass signal to your HTTP call so an attempt stops promptly.
    • Throw LlmProviderError with the most specific kind you can tell, plus retryAfterSeconds when the vendor sends one. failureKindForStatus(status) covers the usual HTTP statuses.
    • Throw LlmContentBlockedError when the vendor's safety filter refused the content.
    • Throw invalid_response for an empty answer instead of returning ''.
    • Anything else you throw is treated as unknown.

    Example: xAI Grok, written by hand to show the interface (for an OpenAI-compatible API like this one, openAiCompatible() does the same in one call):

    import {
  type ConverseRequest,
  failureKindForStatus,
  type ILlmProvider,
  LlmProviderError,
} from '@vetrox/llm-balancer';

type GrokModel = 'grok-4' | 'grok-4-fast' | (string & {});

export class GrokProvider implements ILlmProvider<'grok', GrokModel> {
  readonly name = 'grok';

  constructor(private readonly apiKey: string) {}

  async converse(request: ConverseRequest, model: GrokModel, signal: AbortSignal) {
    const messages = [
      ...(request.system ? [{ role: 'system', content: request.system }] : []),
      ...request.messages.map(({ role, content }) => ({
        role,
        content: typeof content === 'string'
          ? content
          : content.flatMap((p) => (p.type === 'text' ? [p.text] : [])).join('\n'),
      })),
    ];

    const response = await fetch('https://api.x.ai/v1/chat/completions', {
      method: 'POST',
      headers: { Authorization: `Bearer ${this.apiKey}`, 'Content-Type': 'application/json' },
      body: JSON.stringify({ model, messages, max_tokens: request.maxOutputTokens }),
      signal,
    });

    if (!response.ok) {
      const retryAfter = Number(response.headers.get('retry-after'));
      throw new LlmProviderError({
        kind: failureKindForStatus(response.status),
        status: response.status,
        message: `Grok answered with HTTP ${response.status}`,
        retryAfterSeconds: Number.isFinite(retryAfter) ? retryAfter : undefined,
      });
    }

    const text = (await response.json()).choices?.[0]?.message?.content;
    if (!text) throw new LlmProviderError({ kind: 'invalid_response', message: 'Empty answer' });
    return text;
  }
}

    Built-in and custom providers are treated exactly the same way.

    Health store

    Where cooldowns live, and how to share them between instances.

    By default each balancer keeps health in memory (MemoryHealthStore), which is right for one server or one serverless isolate. To share cooldowns between instances, implement IHealthStore: 

    interface IHealthStore {
  get(key: string): Promise<HealthRecord | undefined>;
  set(key: string, record: HealthRecord): Promise<void>;
  delete(key: string): Promise<void>;
}

interface HealthRecord {
  kind: FailureKind;
  reason: string;
  until: number;       // epoch ms; Infinity = until removed
  lastResort: boolean;
}
    • Keys are provider:model.
    • The balancer decides about expiry; a store only keeps records.
    • A store that serializes records must preserve until: Infinity.

    Example with Redis:

    import type { HealthRecord, IHealthStore } from '@vetrox/llm-balancer';

class RedisHealthStore implements IHealthStore {
  constructor(private readonly redis: RedisClient) {}

  async get(key: string) {
    const raw = await this.redis.get(`llm-health:${key}`);
    if (!raw) return undefined;
    const record = JSON.parse(raw);
    return { ...record, until: record.until ?? Infinity }; // JSON has no Infinity
  }

  async set(key: string, record: HealthRecord) {
    const ttl = Number.isFinite(record.until) ? { PXAT: record.until } : {};
    await this.redis.set(`llm-health:${key}`, JSON.stringify(record), ttl);
  }

  async delete(key: string) {
    await this.redis.del(`llm-health:${key}`);
  }
}

new LoadBalancer({ /* ... */ healthStore: new RedisHealthStore(redis) });

    Testing

    Fake the balancer, or keep it and fake a provider.

    Fake the balancer

    Depend on the interfaces ILoadBalancer<Pool> and IModelHandle in your code, and give tests a fake: 

    import type { ILoadBalancer, IModelHandle } from '@vetrox/llm-balancer';

class FakeBalancer implements ILoadBalancer<'default'> {
  model(pool: 'default'): IModelHandle {
    return { pool, converse: () => Promise.resolve('fake answer') };
  }
  status() {
    return Promise.resolve([]);
  }
}

    Keep the real balancer

    Register a scripted provider to test fallback and error handling end to end:

    import { type ILlmProvider, LlmProviderError, LoadBalancer } from '@vetrox/llm-balancer';

const flaky: ILlmProvider<'gemini'> = {
  name: 'gemini',
  converse: (_request, model) =>
    model === 'broken'
      ? Promise.reject(new LlmProviderError({ kind: 'overloaded', message: '503' }))
      : Promise.resolve(`answer from ${model}`),
};

const balancer = new LoadBalancer({
  providers: [flaky],
  pools: {
    default: [
      { provider: 'gemini', model: 'broken' },
      { provider: 'gemini', model: 'working' },
    ],
  },
});
// -> 'answer from working'
